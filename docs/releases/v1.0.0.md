## 1.0.0

第一个正式版：三条链路（评测资料提交、镜像固件上传、豁免草稿）都已对着真实平台跑通并写回工作簿，设置页与 README 定型。

### 评测资料提交

- 填一个设备目录就能跑：自动识别 `OpenHarmony兼容性申请资料.xlsx`，带出 `exemption/`、固件包、外观图、`pcid.sc`、自检表与 `report.zip`。
- 平台五步一路存到「未提交」：联系人 → 产品定义 → 软件定义 → 报告上传（镜像 + XTS 报告 + PCS 自检表）→ 样机寄送（快递单号 + 物品清单）。
- 产品定义与第 4 步都按平台「下一步」语义推进（`isSave:false`），否则平台不会生成报告关联行——这是 0.6.x 之前一直卡在第 4 步的根因。
- 旧版式工作簿读取时就地升级：补「内核」行（按操作系统类型填 Linux / LiteOS-A / LiteOS-M）、去掉「外观图路径」「PCID.sc路径」两行；WPS 占用时只给 warning 不阻断。
- `report/` 目录没有 zip 时，预检自动打包成 `report/report.zip`；已有 zip 且比目录内容新就复用。
- 安全补丁日期自动归一：`2026-11-1` / `2026.1.5` / `2026年03月07日` / `20261101` 都写成 `2026/11/01`。
- 卡片标出「未提交草稿」：哪条能续提交、哪条需人工处理、平台数据是否与工作簿一致。

### 镜像固件上传

- 直接给 `.7z` / `.zip`（也接受 tar 系列）或目录，登录平台「企业空间 → 镜像管理」上传，进度实时回传（解析 → 上传 → 校验）。
- 上传前按文件名查重：已有同名且传完的记录直接跳过，并在面板提示「平台已有这条固件，未重复上传」；同名多条历史记录只提示条数，不删任何记录。
- 预检通过后自动接上固件上传，不需要再点一次按钮。

### 豁免资料

- 「识别目录」只读：列出每个模块的测试套、用例数、平台提交路径与附件（优先 `<套件>-豁免材料.zip`，缺失时用该套件的 `.txt` 直传）。
- 测试套分类按目录自动识别（Acts / ActsValidator / Hats / Dcts / Ssts → 平台 test_type），模块目录与分类目录同名时取最外层，避免歧义。
- 「保存豁免草稿」只存草稿（`status: 0`），查重命中即停，绝不点提交。

### 兼容性与升级

- `dsh.engines.dsh`: `>=0.2.1-rc.1 <0.3.0`；`dshReleases` 标记 0.2.1-rc.1 / 0.2.1-rc.3 / 0.2.2-rc.1 为 compatible。
- 从 0.6.x 升级无需迁移：设置仍在 `~/.dsh/ohos-xts-auto-reporter.json`（0600），旧工作簿首次读取时自动升级版式。
- 宿主半区（路由、工具）与浏览器半区（设置页卡片）都在本包里；装完重启 DSH Desktop 生效。

### 边界

- 只保存草稿，从不调用「确认提交」；豁免同理。
- 不删除平台任何记录；镜像重复行只提示，由你在平台上处理。
- 凭据只存本机 0600 文件或 `OH_USERNAME`/`OH_PASSWORD`，不写日志、不入工作簿、不进仓库。
