## 0.6.5

DSH 0.2.2-rc.1 兼容性申报，以及豁免草稿测试套分类识别的歧义修复。

### DSH 兼容性

- `dsh.engines.dsh` 从 `>=0.2.1-rc.1` 补成 `>=0.2.1-rc.1 <0.3.0`：0.2.x 小版本仍在兼容声明内，0.3.x 不再被 engines 放行。此前没有上界是长期漏项（v0.3.2 起就是无上界），不是本次回归。
- `dsh.compatibility.dshReleases` 新增 `"0.2.2-rc.1": "compatible"`：本机 DSH 0.2.2-rc.1 宿主已加载本插件，`waiver_draft` / `gitlab_cred_status` 工具可用。
- README 兼容性说明的基线同步到 **0.2.2-rc.1**，engines 表述同步为带上下界的完整区间。
- `test/manifest.test.ts` 回归锁同步：engines 断言改为完整区间，并锁住 `0.2.1-rc.1` / `0.2.1-rc.3` / `0.2.2-rc.1` 三个 compatible 标记。

### 豁免资料

- **修复测试套分类误判（T13）**：`detectTestCategory` 原先从报告目录向上取**第一个**可映射的目录名，模块目录恰好叫 `Acts` / `ActsValidator`（例如 `exemption/ActsValidator/ActsValidator/FooTest.txt`）时会把模块目录当成分类型目录，推导出的提交路径基准随之偏移（跨分类同名嵌套时连分类值都会判错）。
- 现在改为取 boundary（扫描根 / `exemption`）之下**最外层**的匹配目录：目录结构正常的资料结果完全不变，只消除歧义分支；`exemption/Acts/<模块>/` 等原有路径有回归测试保护。
- 新增 3 条单测：模块目录名为 `ActsValidator`、模块目录名为另一分类名、单文件输入（无 `rootPath`）时取最外层。
